Kalari runs beside your coding agent on a Linux host. The agent edits the candidate. Kalari compares its output with a separate baseline.

## Install the release

Use Linux x86-64 with glibc 2.35 or newer. Startup and supervisor smoke tests passed on Ubuntu 22.04 and Debian 12. Ubuntu 24.04 remains the deployed host. Binary installation does not require Lean.

```sh
uname -m
getconf GNU_LIBC_VERSION
mkdir -p "$HOME/kalari-download"
cd "$HOME/kalari-download"
curl -fLO https://github.com/nrynss/kalari/releases/download/v0.1.3/kalari-0.1.3-linux-x86_64.tar.gz
curl -fLO https://github.com/nrynss/kalari/releases/download/v0.1.3/SHA256SUMS
sha256sum -c SHA256SUMS
tar -xzf kalari-0.1.3-linux-x86_64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m755 kalari-0.1.3-linux-x86_64/bin/kalari "$HOME/.local/bin/kalari"
install -m755 kalari-0.1.3-linux-x86_64/bin/kalari-aashaan "$HOME/.local/bin/kalari-aashaan"
export PATH="$HOME/.local/bin:$PATH"
kalari --version
```

Expect `kalari 0.1.3`. Add the PATH setting to your shell configuration. Upgrade by replacing both binaries.

[Release assets and runtime-library report](https://github.com/nrynss/kalari/releases/tag/v0.1.3).

## Install host dependencies

The demonstrated versions are Microsandbox 0.7.13, Lambo 0.9.0, Vimanam 2.1.0, and OpenCode 2.2.5.

| Tool | Host role |
|---|---|
| `msb` | Creates microVMs through KVM |
| `lambo` | Runs as a child process for graph memory |
| `vimanam` | Compares API specifications |
| `curl` | Makes inference requests |
| `rg` | Searches consumer code |
| `getent` | Resolves API destinations |
| `python3` | Executes service startup checks |

On Ubuntu:

```sh
sudo apt-get update
sudo apt-get install -y curl ripgrep python3 xz-utils
curl -fsSL https://install.microsandbox.dev -o /tmp/install-microsandbox.sh
# Review the downloaded installer before running it.
sh /tmp/install-microsandbox.sh
msb --version
```

Keep `msb` in its installed location. Copying the executable elsewhere can break discovery of its runtime libraries.

Download the tested Lambo and Vimanam releases.

```sh
cd "$HOME/kalari-download"
curl -fLO https://github.com/nrynss/lambo/releases/download/v0.9.0/lambo-0.9.0-linux-x86_64
curl -fLO https://github.com/nrynss/lambo/releases/download/v0.9.0/lambo-0.9.0-linux-x86_64.sha256
sha256sum -c lambo-0.9.0-linux-x86_64.sha256
install -m755 lambo-0.9.0-linux-x86_64 "$HOME/.local/bin/lambo"

curl -fLO https://github.com/noemaforge/vimanam/releases/download/v2.1.0/vimanam-x86_64-unknown-linux-gnu.tar.xz
curl -fLO https://github.com/noemaforge/vimanam/releases/download/v2.1.0/vimanam-x86_64-unknown-linux-gnu.tar.xz.sha256
sha256sum -c vimanam-x86_64-unknown-linux-gnu.tar.xz.sha256

lambo --version
vimanam --version
```

## Prepare virtualization

Run these checks on the Linux host that will execute Kalari.

```sh
test -r /dev/kvm && test -w /dev/kvm
umask 022
msb doctor
for attempt in 1 2 3; do
  msb pull python:3.13-slim && break
  test "$attempt" -lt 3 || exit 1
  sleep 2
done
```

Fix KVM access before continuing. Cloud guests need exposed virtualization support. Check the actual VM before choosing a deployment.

Microsandbox refuses group-writable storage. Keep `umask 022` for shell commands and `UMask=0022` for systemd.

Kalari uses cached images with `--pull never`. It copies the workspace and supervisor into each guest and sets guest overcommit before execution.

The default image supplies Python 3.13. Include other runtime dependencies in a prepared image before running the consumer.

## Create the session directories

Keep the original consumer separate from the candidate. All four workspace directories must exist and resolve canonically.

```sh
export KALARI_WORK="$(realpath -m "$HOME/kalari-work")"
mkdir -p "$KALARI_WORK"/{baseline,candidate,checks,evidence}
```

Copy the original consumer into `baseline`. Copy the project the agent will edit into `candidate`. Place both API specifications outside these workspaces.

The baseline command must produce the old API's complete output. The candidate must emit comparable JSONL records with nonempty string IDs.

The differential counts missing, extra, duplicated, and changed records. Supply comparable input data and account for intentional transformations.

## Configure endpoints and limits

Save this as `$KALARI_WORK/kalari.json`. Replace the Lambo paths with canonical paths from your machine.

```json
{
  "models": {
    "endpoint": "https://api.vultrinference.com/v1",
    "model": "deepseek-v4.1-flash-1017",
    "api_key_env": "KALARI_INFERENCE_KEY"
  },
  "decisions": {
    "endpoint": "https://api.vultrinference.com/v1/systemone",
    "model": "clef",
    "api_key_env": "KALARI_INFERENCE_KEY"
  },
  "sandbox": {
    "backend": "microsandbox",
    "image": "python:3.13-slim",
    "caps": {
      "timeout_ms": 30000,
      "output_cap_bytes": 65536,
      "memory_mib": 512
    },
    "allowlist": [
      {"host": "api.example.test", "port": 443}
    ]
  },
  "lambo": {
    "command": ["/absolute/path/to/lambo", "serve"],
    "config_path": "/absolute/path/to/lambo.toml"
  }
}
```

Replace `api.example.test` with your actual API hostname. An empty allowlist is valid for a consumer using local fixture data.

Production requires Microsandbox. Although the parser recognizes Docker, the production session validator does not accept that backend.

The Clef decision endpoint and model are fixed by production validation. Keep the shown System One endpoint and `clef` model.

## Configure the migration

Save this as `$KALARI_WORK/session.json`. Replace every absolute path and the baseline command.

```json
{
  "session_id": "migration",
  "repo_scope": "my-project",
  "workspace": "/absolute/path/to/kalari-work/candidate",
  "old_spec": "/absolute/path/to/spec-v1.yaml",
  "new_spec": "/absolute/path/to/spec-v2.yaml",
  "baseline": {
    "workspace": "/absolute/path/to/kalari-work/baseline",
    "command": ["python3", "consumer.py"],
    "caps": {
      "timeout_ms": 30000,
      "output_cap_bytes": 65536,
      "memory_mib": 512
    },
    "allowlist": [{"host": "api.example.test", "port": 443}]
  },
  "check_workspace": "/absolute/path/to/kalari-work/checks",
  "evidence_workspace": "/absolute/path/to/kalari-work/evidence",
  "artifact": "records.jsonl",
  "aashaan": "/absolute/path/to/kalari-aashaan",
  "tool_path": "/absolute/path/to/tools:/usr/local/bin:/usr/bin:/bin"
}
```

The directories must remain distinct and must not nest inside one another. Specs and executables must exist. Use `realpath` to resolve symlinks.

`tool_path` controls host subprocess discovery. It must include `msb`, `rg`, `vimanam`, `curl`, and `getent`.

The guest process has its own fixed PATH. Kalari translates a leading `python3` command for the demonstrated Python image.

The baseline has its own command and allowlist. Its caps and destinations must fit within `sandbox.caps` and `sandbox.allowlist`.

`artifact` names a non-hidden file at each workspace root. Kalari removes stale output before execution. The command must write a fresh file.

## Configure Lambo and credentials

Use a separate SQLite store for your project. Save the following configuration at the path named in `lambo.config_path`.

```toml
promotion_policy = "Solo"

[store]
kind = "sqlite"
path = "/absolute/path/to/lambo.db"

[embedder]
kind = "openai"
url = "https://api.vultrinference.com"
model = "qwen3-embedding-4b"
dim = 2560
api_key_env = "KALARI_INFERENCE_KEY"

[serve]
default_session = "migration"
```

Load the inference key through your secret manager. For the demonstrated Linux keyring entry:

```sh
export KALARI_INFERENCE_KEY="$(secret-tool lookup service vultr-inference account kalari)"
test -n "$KALARI_INFERENCE_KEY"
lambo provision --config /absolute/path/to/lambo.toml
```

Use your own keyring entry if its name differs. Configuration files contain environment variable names. Key values stay in the host environment.

The coding agent has its own model configuration. Kalari's Clef requests and Lambo embeddings also use inference access.

## Start the server and connect your agent

The server takes two positional configuration paths.

```sh
kalari serve "$KALARI_WORK/kalari.json" "$KALARI_WORK/session.json"
```

It reads MCP messages from standard input. A quiet terminal means it is waiting for a client.

The <DocLink to="mcp/">MCP guide</DocLink> provides OpenCode setup, discovery commands, and complete tool arguments.

## Try a local fixture first

This example writes two records without contacting an API. It exercises the artifact contract before you adapt a real consumer.

The setup creates a fresh directory. It downloads the release's recorded API specifications and writes complete configuration files.

```sh
export KALARI_WORK="$(realpath -m "$HOME/kalari-fixture")"
python3 - <<'PY'
import json
import os
from pathlib import Path
import shutil
import urllib.request

root = Path(os.environ["KALARI_WORK"]).resolve()
root.mkdir(exist_ok=False)
for name in ("candidate", "baseline", "checks", "evidence"):
    (root / name).mkdir()
program = r"""import json
from pathlib import Path
rows = [{"id": "a", "amount": 100}, {"id": "b", "amount": 200}]
Path("records.jsonl").write_text("".join(json.dumps(row) + "\n" for row in rows))
"""
for name in ("candidate", "baseline"):
    (root / name / "consumer.py").write_text(program)
repo = "https://raw.githubusercontent.com/nrynss/kalari/v0.1.3"
specs = "bench/workspaces/payout-sync/specs"
for version in ("v1", "v2"):
    urllib.request.urlretrieve(
        f"{repo}/{specs}/openapi-{version}.yaml",
        root / f"spec-{version}.yaml",
    )
def executable(name):
    value = shutil.which(name)
    if not value:
        raise SystemExit(f"Missing executable: {name}")
    return str(Path(value).resolve())
caps = {"timeout_ms": 30000, "output_cap_bytes": 65536, "memory_mib": 512}
endpoint = {
    "endpoint": "https://api.vultrinference.com/v1",
    "model": "deepseek-v4.1-flash-1017",
    "api_key_env": "KALARI_INFERENCE_KEY",
}
config = {
    "models": endpoint,
    "decisions": {
        **endpoint,
        "endpoint": "https://api.vultrinference.com/v1/systemone",
        "model": "clef",
    },
    "sandbox": {
        "backend": "microsandbox", "image": "python:3.13-slim",
        "caps": caps, "allowlist": [],
    },
    "lambo": {
        "command": [executable("lambo"), "serve"],
        "config_path": str(root / "lambo.toml"),
    },
}
session = {
    "session_id": "local-fixture", "repo_scope": "local-fixture",
    "workspace": str(root / "candidate"),
    "old_spec": str(root / "spec-v1.yaml"),
    "new_spec": str(root / "spec-v2.yaml"),
    "baseline": {
        "workspace": str(root / "baseline"),
        "command": ["python3", "consumer.py"],
        "caps": caps, "allowlist": [],
    },
    "check_workspace": str(root / "checks"),
    "evidence_workspace": str(root / "evidence"),
    "artifact": "records.jsonl",
    "aashaan": executable("kalari-aashaan"),
    "tool_path": os.environ["PATH"],
}
for name, data in (("kalari.json", config), ("session.json", session)):
    (root / name).write_text(json.dumps(data, indent=2) + "\n")
(root / "lambo.toml").write_text(
    'promotion_policy = "Solo"\n'
    '[store]\nkind = "sqlite"\n'
    f'path = "{root / "lambo.db"}"\n'
    '[embedder]\nkind = "openai"\n'
    'url = "https://api.vultrinference.com"\n'
    'model = "qwen3-embedding-4b"\ndim = 2560\n'
    'api_key_env = "KALARI_INFERENCE_KEY"\n'
    '[serve]\ndefault_session = "local-fixture"\n'
)
print(root)
PY
lambo provision --config "$KALARI_WORK/lambo.toml"
```

Keep the inference environment variable set from the preceding step. Follow the <DocLink to="mcp/">MCP guide</DocLink> for tool discovery and requests.

For this fixture, the candidate command is `["python3", "consumer.py"]` and the allowlist is empty. Both artifacts should contain identical records.

Change one candidate amount to exercise a failing differential. This fixture tests the wiring, not a vendor migration.

Tool discovery does not require a model request. Sandbox calls can invoke recall and embedding services, even when the consumer itself reads local data.


## Network policy

The guest's loopback address refers to the guest itself. A host-side API needs an address reachable from that guest.

Kalari resolves API hostnames on the host and supplies explicit IP rules. This avoids the recorded TLS domain-rule failure in Microsandbox 0.7.13.

The guest starts with default-deny networking and an empty environment. Consumers requiring vendor credentials need a trusted access design outside the guest.

## Outcomes and evidence

A probe can exit successfully without producing the artifact. That returns `passed=false` with a missing-artifact explanation.

A timeout returns `killed_timeout`. A log flood can return `killed_output_cap`. The process verdict and verification result remain separate.

Evidence lives at `$KALARI_WORK/evidence/.kalari/evidence.jsonl`. The MCP result names the run ID.

Starting MCP does not publish a website. The <DocLink to="vultr/">Vultr guide</DocLink> covers Caddy and the read-only evidence API.

The key-shape check rejects ASCII-alphanumeric runs of 32 or more characters, including commit SHAs and hex digests passed as command arguments.

## Troubleshooting

| Symptom | Action |
|---|---|
| Command not found | Add the installation directory to PATH |
| Unsupported GLIBC version | Use the supported host or build on the target system |
| KVM check fails | Enable virtualization and grant access to the executing user |
| Storage permits path substitution | Correct storage permissions and use `umask 022` |
| Image pull fails | Retry preparation before starting the migration |
| Session path missing or noncanonical | Create the path and resolve it with `realpath` |
| No artifact | Run the consumer that writes the configured filename |
| Unsupported backend or decision configuration | Use Microsandbox and the shown Clef settings |
| Observer rejected | Remove observer configuration from production |
| MCP server exits immediately | Run its command manually and inspect stderr |

Inspect the exact sandbox name before cleaning up an interrupted run. Remove only your own sandbox with `msb remove -f NAME`.

Production rejects observer configuration. The frozen benchmark published zero lessons and measured no learned-memory benefit.

## Build from source

Install elan first. The repository selects Lean 4.35.0. Install ripgrep before building.

```sh
git clone https://github.com/nrynss/kalari.git
cd kalari
lake build kalari kalari-aashaan
./tools/check.sh
```

The offline self-test uses repository fixtures. Run it from a checkout. It is not an installed-binary health check.
