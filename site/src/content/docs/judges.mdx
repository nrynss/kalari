This page walks every result in the order of the [demo video on the submission page](https://lablab.build/ai-hackathons/vultr-hackathon/kalari/kalari-contained-rehearsals-for-api-upgrades). Every number below comes from `slides/data/results.json`: three models, three upgrades, five repeats each way, plus the filmed takes it names. The method, the cost rule, and the limits sit on the <DocLink to="evidence/">Evidence and limits</DocLink> page.

Both arms run the same OpenCode 2.2.5 with the same model on Vultr Serverless Inference. Alone means microsandbox-mcp with no Kalari tools. With Kalari means the `kalari serve` MCP entry. The only difference is whether Kalari is plugged in.

## The problem

The reference run motivates the whole project. GLM 5.3 Flash migrates a payments importer, calls the API own `/v2/verify`, and reports the upgrade verified. The hidden grader counts 23 records with wrong amounts: FAIL, 23 mismatched. The process said success and lost the data. The same failure shipped alone on DeepSeek V4.1 Flash and MiMo V2.6 Flash. Source: `takes/2026-11-08-user-glm-disbursements-reference.mkv`, results.json `facts.problem`.

## The fix

Same model, with Kalari. Every record is checked against the old API. PASS, all 2,341 of 2,341. Source: `takes/2026-11-08-user-glm3-disbursements-kalari.mkv` (Kalari 0.2.3), results.json `facts.fixed`.

## Learning across upgrades

One project and one store stay shared across three upgrades in order: payouts, settlements, disbursements. On payouts the observer saw records repeat at page boundaries, a token on the last page, and a 429 answered by retrying the identical request. That became one lesson. Read how the lesson is written and enforced on the <DocLink to="learn/">How Kalari learns</DocLink> page.

Next session, settlements recalled the lesson, the agent quoted it back, and passed first time: 1,873 of 1,873 in 27.7 s at $0.012. Disbursements recalled it too and passed first time: 2,341 of 2,341 in 21.5 s at $0.009. Payouts wrote at $0.026 and 57.4 s. That per-step drop is one filmed chain, not a repeat statistic. DeepSeek and MiMo learned the same way: settlements recalled 5 of 5 for both. Sources: `takes/2026-11-08-user-glm3-{payouts,settlements,disbursements}-kalari.mkv`, the settlement agent quote in its events file, results.json `facts.learning` and `chain`.

## Across three models

Three models, three upgrades, five times each. With Kalari, all 45 passed. Alone, 34: disbursements failed 11 times in 15. Payouts and settlements passed alone for every model, 15 of 15 each, so the pass-rate edge sits in disbursements. Nothing here says DeepSeek verifies on its own: alone it failed disbursements 4 of 5.

| Model | Payouts alone / Kalari | Settlements alone / Kalari | Disbursements alone / Kalari |
|---|---|---|---|
| DeepSeek V4.1 Flash | 5/5, 5/5 | 5/5, 5/5 | 1/5, 5/5 |
| GLM 5.3 Flash | 5/5, 5/5 | 5/5, 5/5 | 0/5, 5/5 |
| MiMo V2.6 Flash | 5/5, 5/5 | 5/5, 5/5 | 3/5, 5/5 |

Passed means the hidden grader passed the final file, of 5 sessions per cell. One repeat each way for Qwen3.8 27B and Muse Glimmer 30B sits outside this grid by user decision. Source: `repeats-table.txt` (aggregate over the repeat rows, groups arm-scenario-model), Kalari 0.2.3, results.json `grid`.

## The numbers

Across all 45 sessions each way, Kalari cost 2.8 times less and finished 2.8 times faster, and passed every session:

- Cost per session: $0.024 with Kalari against $0.067 alone.
- Wall time per session: 58 s with Kalari against 166 s alone.
- Passed the hidden grader: 45 of 45 with Kalari against 34 of 45 alone.

Earlier baseline, the frozen 60-session DeepSeek benchmark: $0.019 vs $0.082 per session (<RepoLink path="bench/RESULTS.md">bench/RESULTS.md</RepoLink> section 2). Alone includes 2 sessions stopped at the 900 s cap. Source: results.json `numbers`.

## Containment

Two runs stand outside the comparison. They are ordinary published runs with the same caps and the same allowlist shape as a Kalari consumer run. No agent wrote either consumer. Read the full scene at <DocLink to="containment/">Containment</DocLink>.

- Run 1: the reference cursor loop crashed on the API 429 after 437 ms. The cap never came into play. Verdict `exited` with exit code 1.
- Run 2: the paced retry loop fetched 68 pages, then the aashaan killed it at 5,009 ms against the 5,000 ms cap. Verdict `killed_timeout`.
- The boundary: one allowed port answered, four unnamed targets refused. Cleanup removed every sandbox and left no child process.

## What this does not show

The table shows cost, wall time, and correctness for the repeat rows. Five repeats per cell is a small sample. Treat every count as raw. Do not generalize beyond these APIs and models. No Kalari session ran in a project whose store lacked the payouts lesson, so there is no Kalari-without-lesson arm to compare against. The limits use the same tone as the results.
