What Kalari is

A rehearsal arena for API upgrades.

Kalari plugs into the coding agent you already use over MCP and rehearses an API upgrade in a contained arena. It works out what changed and what it touches. It runs the new code in a throwaway microVM against the real API, with the old version as the reference. It records what the run proved.

The agent writes the code, and Kalari decides what has to be checked and whether it passed.

  • what_changedLists the changes between two API versions, with stable change IDs.
  • blast_radiusFinds the callers and tests each change touches.
  • recall_lessonsReturns lessons for these change kinds as checks that must pass.
  • run_in_sandboxRuns the new code in a throwaway microVM behind the proved gate. It returns the verdict and logs.
  • record_lessonStores what a verified run showed about the API, keyed by change kind.

The five tools live in Kalari/Mcp.lean on GitHub. The gate is proved, not just tested. Four theorems cover the workspace, the network, the caps and the secrets: decide_workspace, decide_network, decide_caps, decide_secrets.

Use it in three steps.

  1. Run kalari serve with a config file and a session file.
  2. Add Kalari to your agent as an MCP server: 
    {
  "mcp": {
    "servers": {
      "kalari": {
        "type": "local",
        "command": ["kalari", "serve", "kalari.json", "session.json"]
      }
    }
  }
}
  3. Ask your agent to upgrade the consumer. Kalari checks each run and records the evidence.
